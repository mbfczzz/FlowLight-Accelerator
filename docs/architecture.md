# 当前实施架构

原方案保存于 original-architecture.md；其中 Java / Spring Boot 已按用户要求替换为 Go。本文件与源码描述当前实现。

Windows WPF UI 通过受访问控制的命名管道调用 Windows Service。服务管理账号、设备、会话、核验过的 Mihomo、游戏规则、探测和停止恢复。

Windows 网络子进程归属带 KILL_ON_JOB_CLOSE 的 Job Object；本地服务意外退出时系统回收它们。控制 API 的临时网络/5xx 故障可维持到既有租约截止，服务按 HTTP 服务端时间换算本机截止时间。TUN 的真实路由与 DNS 恢复仍需安装后验收。

控制服务采用 Go 标准库 HTTP、GORM、MySQL，按账号、目录、线路、会话和节点模块组织，部署为模块化单体。SQLite 用于本地开发，Redis 用作可重建的租约辅助索引。

节点 Agent 使用独立令牌和客户端证书，只接受结构化任务。它启动校验过的 ssserver、sslocal、Realm，并管理进程、配置和租约。没有远程任意 shell 接口。

游戏数据经过 Mihomo、入口、中转、落地；管理 API、网页和数据库处理授权与配置。

## 一致性

会话在 SQL 事务中校验幂等键、设备、用户额度、线路权限、落地与容量。当前用数据库协调记录序列化资源变更，保证多实例预留一致性；扩大规模时可拆成设备和线路锁。

规则和线路版本不可变。发布通过验证会话执行真实进程与路径探测，成功后更新发布指针；失败、取消和过期保留旧版本并回收资源。

托管会话使用独立端口和进程，SS2022 密钥承担协议认证，Realm 端口号不构成认证。

停止先撤销进程；节点确认或租约与宽限到期后释放预留。生产 systemd cgroup 与父进程死亡信号保证 Agent 退出后的子进程边界。

## 身份与凭据

密码使用 bcrypt；访问令牌为高熵随机值，数据库保存哈希。刷新令牌轮换，旧令牌重用撤销整个令牌族。

节点使用一次性注册凭据申请 P-256 证书，生产要求 mTLS 和匹配的节点令牌。协议密钥使用 AES-GCM 加密，普通目录只返回凭据引用；用户只能读取自己的会话连接配置。

## 状态与观测

节点路径验证和客户端本机探测分别记录。客户端完成实际回包后才报告 ACTIVE。界面区分线路探测值和游戏内延迟。

/metrics 输出真实会话状态计数；审计记录配置、发布与会话操作。首版不采集游戏通信内容。

## 验证

Go 测试覆盖控制接口、事务、权限和真实转发进程；可以使用 SQLite 或 CI MySQL。C# 检查程序验证协议、令牌与规则，Windows 项目独立编译。网页后台执行类型检查、构建和真实 API 交互检查。
