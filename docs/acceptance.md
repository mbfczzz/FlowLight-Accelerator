# 验收与运行边界

## 自动验证

- 未登录、玩家访问管理接口、刷新令牌重用。
- 同键重复创建、同键更换参数、并发创建和设备占用。
- 线路与端口容量、停止幂等、过期回收。
- 私有落地访问隔离、撤销权限后停止续租。
- 节点任务归属、claim 校验和探测证据。
- UDP 失败或出口不符时不进入连接就绪状态。
- 凭据加密、列表与日志脱敏。
- C# API 契约、HTTPS 限制、令牌刷新和幂等键。
- SS2022 + Realm 真实本机 TCP / UDP 转发与租约关闭。
- 一次性节点注册与真实 TLS 客户端证书握手。
- 规则回滚后继续递增版本，取消线路验证保留已发布版本。
- Windows Job Object 回收所属子进程，503 网关错误归类为暂时故障。
- 验证完成后的撤销失败不改变已发布版本；运行进程失败上报后会话停止，迟到事件不报错。
- 节点心跳只写 Agent 字段，不会恢复管理员已禁用的节点，也不覆盖声明能力；中转节点不接收会话密钥。
- 节点证书续期：旧证书在新证书首次使用前有效，之后失效；operator 可从管理接口停止会话。
- Agent 等待监听就绪才报告准备成功；进程意外退出按退避重启，耗尽后上报；正常停机保留运行记录并在重启后恢复；损坏记录隔离。
- 客户端探测使用固定送入隧道的专用入站，不受服务进程 DIRECT 规则影响；Mihomo 关闭 IPv6；损坏的内核记录不阻止服务启动。
- 探测服务只信任指定代理网段的 X-Forwarded-For；UDP 回显按来源限速。
- 登录按地址和账号限流，可信代理才能指定真实客户端地址；内部错误返回 500 且不泄露数据库信息；重复用户名返回明确的 400。
- 最新客户端版本按版本号选取，编辑旧版本不改变其创建时间；管理列表分页不重复、不遗漏；/metrics 支持长期只读抓取凭据。
- 玩家自带落地只接受公网地址并限制数量；过期令牌、旧幂等键和已结束任务定期清理。
- 线路探测复用同一隧道连接计时，UDP 5 包至少回 4 包，并上报丢包率；配置 PROBE_NODE_ID 时由该 Agent 验证托管线路。

2026-10-14 本地联调使用 shadowsocks-rust v1.25.0 与 Realm v2.9.6，经校验的 Windows 原生程序完成本机三次 TCP / UDP 回包与停止检查。该结果只证明本机协议链路，不代表公网或游戏内延迟。测试端口同时检查 TCP 与 UDP 可用性。

客户端 UI 用 tools/windows-ui-harness 的替身服务驱动完整流程并截图核对：自动弹出登录框、账号预填、游戏列表滚动、下拉框显示线路名、开始后按钮变"正在连接…"再变"加速中"、延迟按阈值着色并显示真实出口、客户端重启后恢复运行中会话的游戏/区服/线路、关闭缩到托盘且再次启动只唤醒原实例；对真实已安装服务验证了普通用户权限下的 SCM 身份校验。

第三轮走查后补齐：控制服务返回的英文原因（账号密码错误、线路满员、设备已有会话等）和会话结束原因在客户端一律显示为中文，未知原因原样透传；已登录时点“账号登录”弹出的是“切换账号”；按钮只在键盘导航时显示焦点框，鼠标点击后不再残留；右侧连接面板顶端对齐，窗口拉高时不再出现大片空白。

视觉重做后用替身服务重跑 drive/explore 两套走查并逐张核对：深色标题栏、登录框、下拉列表、提示条四种着色、加速中状态、本地服务断开、900×650 与最大化网格；锁定期间游戏列表不再出现系统默认的白底。

第五轮按用户视角的走查意见重做布局：游戏库移到左侧并带搜索，账号操作收进头像菜单，开始/停止合并为一个按钮，失败原因内联在按钮下方，短暂反馈改为右下角提示，线路下拉显示延迟且不可用项不可选，未发布游戏不再列出，所有系统术语改为玩家语言。替身服务两套走查全部通过（drive 8 步、explore 17 个状态），逐张核对了登录框、下拉、加速中、账号菜单、服务断开、900×650 与最大化。

第六轮按 UU / 雷神 / 夸克的图文风格重做：封面卡片游戏库、横幅游戏页、区服卡片、带信号格与负载的线路列表、圆形加速按钮（连接中流光转动）、实时延迟/抖动/丢包/时长面板与延迟走势图、图标导航与配图空状态、左图右表单的登录框。本地服务新增 active_since，客户端重启后已加速时长不归零。替身服务改为提供线路负载和带时间戳、会变化的检测值；drive 与 explore 两套走查全部通过，截图逐张核对了 1120×750、900×650 与最大化下的游戏库、游戏页、连接中、加速中、加速时的游戏库、登录、账号菜单、启动被拒、搜索无结果和本地服务断开。

管理后台细节检查：控制服务返回给后台和客户端的错误全部改为中文并说明具体字段与规则（原先多数是英文或笼统的“invalid resource configuration”）；玩家密码下限改为 8 位，管理与运维仍为 14 位，玩家升为管理角色须同时设新密码；账号名去首尾空格（原先带空格的账号无法登录）、按字符数限制 100 以内（原先按字节可超出数据库列宽）；后台表单提交前校验、标签写明范围；列表中的用户名不再被翻译成角色名（账号 admin 曾显示为“管理员”），编号显示为名称，会话列表增加用户列；保存提示只对游戏规则和线路提示需要发布；结束原因、审计操作、任务类型等显示中文；后台标志换成与客户端一致的流光标志。本地用控制服务与后台的实际页面逐项点击验证：错误密码、玩家 7 位与 8 位密码、运维 12 位密码、玩家升运维不设密码、重复账号、http 下载地址、审计操作人与操作、中文搜索。

后台通过真实 API 完成登录、规则保存和发布；Windows 通过真实命名管道完成登录、设备登记和游戏目录读取。管理端桌面/窄屏以及客户端 1120×750、900×650 均检查了显示与空状态。未启用 TUN。

## 真实游戏验收：尚待线路和区服

VALORANT、英雄联盟分别记录游戏版本、系统、运营商、区服、节点和内核版本。

1. 核对游戏主进程、登录器和语音；不默认接管所有关联进程。
2. 记录实际规则命中和出口，验证其他应用直连。
3. 比较游戏内延迟、丢包和抖动；入口 RTT 不替代游戏 RTT。
4. 完成登录、匹配、语音和完整对局。
5. 验证停止、启动失败、内核退出、服务重启、休眠和切网。
6. 模拟 API 中断，检查有效租约续行及过期后的实际关闭。
7. 模拟节点崩溃、端口冲突、发布失败，确认旧版本保留。
8. 验证固定出口和独享资源不串用，普通切线按可能重连处理。
9. IPv6 未实测时保持关闭，当前托管监听实现为 IPv4。
10. 分发前完成签名、驱动、内核许可和安装升级验证。

## 已知交付边界

本地验证未开启 TUN，没有改动工作机路由、DNS、防火墙。未取得真实游戏线路凭据，不提供“韩服已可用”“已降低延迟”等无证据结论。

导入的第三方静态凭据由第三方管理；平台停止会话记录不能代替远端撤销。托管进程按租约关闭。

首版游戏由用户自行启动，进程命中需实测。断线出口保护、无感切换与自动升级不在首版已验证能力内。
