# 验收与运行边界

## 自动验证

- 未登录、玩家访问管理接口、刷新令牌重用。
- 同键重复创建、同键更换参数、并发创建和设备占用。
- 线路与端口容量、停止幂等、过期回收。
- 私有落地访问隔离、撤销权限后停止续租。
- 节点任务归属、claim 校验和探测证据。
- UDP 失败或出口不符时不进入连接就绪状态。
- 凭据加密、列表与日志脱敏。
- C# API 契约、HTTPS 限制、令牌刷新和幂等键。
- SS2022 + Realm 真实本机 TCP / UDP 转发与租约关闭。
- 一次性节点注册与真实 TLS 客户端证书握手。
- 规则回滚后继续递增版本，取消线路验证保留已发布版本。
- Windows Job Object 回收所属子进程，503 网关错误归类为暂时故障。
- 验证完成后的撤销失败不改变已发布版本；运行进程失败上报后会话停止，迟到事件不报错。
- 节点心跳只写 Agent 字段，不会恢复管理员已禁用的节点，也不覆盖声明能力；中转节点不接收会话密钥。
- 节点证书续期：旧证书在新证书首次使用前有效，之后失效；operator 可从管理接口停止会话。
- Agent 等待监听就绪才报告准备成功；进程意外退出按退避重启，耗尽后上报；正常停机保留运行记录并在重启后恢复；损坏记录隔离。
- 客户端探测使用固定送入隧道的专用入站，不受服务进程 DIRECT 规则影响；Mihomo 关闭 IPv6；损坏的内核记录不阻止服务启动。
- 探测服务只信任指定代理网段的 X-Forwarded-For；UDP 回显按来源限速。
- 登录按地址和账号限流，可信代理才能指定真实客户端地址；内部错误返回 500 且不泄露数据库信息；重复用户名返回明确的 400。
- 最新客户端版本按版本号选取，编辑旧版本不改变其创建时间；管理列表分页不重复、不遗漏；/metrics 支持长期只读抓取凭据。
- 玩家自带落地只接受公网地址并限制数量；过期令牌、旧幂等键和已结束任务定期清理。
- 线路探测复用同一隧道连接计时，UDP 5 包至少回 4 包，并上报丢包率；配置 PROBE_NODE_ID 时由该 Agent 验证托管线路。

2026-10-14 本地联调使用 shadowsocks-rust v1.25.0 与 Realm v2.9.6，经校验的 Windows 原生程序完成本机三次 TCP / UDP 回包与停止检查。该结果只证明本机协议链路，不代表公网或游戏内延迟。测试端口同时检查 TCP 与 UDP 可用性。

客户端 UI 用 tools/windows-ui-harness 的替身服务驱动完整流程并截图核对：自动弹出登录框、账号预填、游戏列表滚动、下拉框显示线路名、开始后按钮变"正在连接…"再变"加速中"、延迟按阈值着色并显示真实出口、客户端重启后恢复运行中会话的游戏/区服/线路、关闭缩到托盘且再次启动只唤醒原实例；对真实已安装服务验证了普通用户权限下的 SCM 身份校验。

管理后台视觉重做，与客户端统一：深色石墨侧栏按“配置 / 账号 / 运行”分组，琥珀色流光标志与主按钮；总览为四个图标指标和“上线准备”清单（按控制服务返回的游戏、节点、端点、线路、玩家数量判断每一步是否完成，总览接口为此新增 published_games、nodes、endpoints、lines、players 计数）；列表首列带生成封面、头像或图标，区服显示为代码＋中文名标签，状态为带圆点的彩色标签，时间显示为“几分钟前”；编辑改为右侧抽屉，字段分组，区服和进程用标签输入（回车添加、可一次粘贴多行、常用区服一键添加），限定游戏和用户可输入名称搜索、选项带封面或头像，线路路径标明入口 / 中转 / 落地并可上下移动；校验失败时出错字段标红、错误写在字段下方并自动滚动聚焦；线路的排空、版本记录和终止收进“更多”菜单；确认框按危险程度着色；登录页为深色流光品牌面板。总览指标颜色表示状态（有则绿、有节点 / 线路 / 游戏但一个都未在线 / 验证 / 发布则琥珀、其余灰）。线路列表显示发布与验证进度（已验证上线、验证中、新版本验证中、验证未通过，未通过的原因直接写在下方），控制服务为此在线路上返回最新版本的状态和错误。游戏封面颜色由控制服务返回的 cover_index 决定：游戏创建时分配并保存（已有最大值加一），之后新增游戏不会改变已有游戏的颜色，升级时已有游戏按 id 顺序补齐；后台与客户端用同一组色相，同一款游戏两边颜色一致。区服在列表、节点和编辑抽屉里都显示为按位置着色的代码标签加中文名，未选的建议项为灰色。手机宽度下侧栏变为顶栏加菜单面板，列表每行变为卡片。本地用种子数据（2 款游戏、2 个节点、2 个端点、2 条线路、4 个账号）在 1440×900 和 390 宽度下截图核对了登录、总览、各列表、各编辑抽屉、更多菜单、终止确认、校验错误、详情、空状态、审计、手机菜单和手机列表；客户端用替身服务跑通 drive.ps1，游戏库封面颜色与 cover_index 对应。

游戏封面图片：后台游戏编辑抽屉新增“封面”，可上传 JPG / PNG / WebP（至少 640×360，不超过 10 MB），上传前按客户端的游戏库卡片和游戏页横幅预览裁切效果；保存游戏时生效，不需要发布规则。控制服务把图片居中裁成 16:9、缩到最宽 1280 并重新编码为 JPEG，按 SHA-256 存在数据库里，通过 `/api/client/v1/covers/<sha256>` 免登录提供并长期缓存；保存游戏不会改动封面，移除后无人使用的图片会被删除。客户端从状态里的控制服务地址下载，校验 SHA-256 后缓存到 `%LOCALAPPDATA%\FlowLightAccelerator\covers`，取不到时继续用生成封面。仓库和安装包不附带任何游戏官方图片，图片由运营方上传并自行确认授权。本地验证：Go 测试覆盖非图片与过小图片被拒、1280×720 输出、内容与名称一致、304 缓存、保存不改封面、移除后删除；后台用占位测试图走查了上传、过小图片提示、预览、列表与手机宽度；客户端连本地控制服务下载并显示了两张占位封面，未上传的游戏仍为生成封面。

后台通过真实 API 完成登录、规则保存和发布；Windows 通过真实命名管道完成登录、设备登记和游戏目录读取。管理端桌面/窄屏以及客户端 1120×750、900×650 均检查了显示与空状态。未启用 TUN。

## 真实游戏验收：尚待线路和区服

VALORANT、英雄联盟分别记录游戏版本、系统、运营商、区服、节点和内核版本。

1. 核对游戏主进程、登录器和语音；不默认接管所有关联进程。
2. 记录实际规则命中和出口，验证其他应用直连。
3. 比较游戏内延迟、丢包和抖动；入口 RTT 不替代游戏 RTT。
4. 完成登录、匹配、语音和完整对局。
5. 验证停止、启动失败、内核退出、服务重启、休眠和切网。
6. 模拟 API 中断，检查有效租约续行及过期后的实际关闭。
7. 模拟节点崩溃、端口冲突、发布失败，确认旧版本保留。
8. 验证固定出口和独享资源不串用，普通切线按可能重连处理。
9. IPv6 未实测时保持关闭，当前托管监听实现为 IPv4。
10. 分发前完成签名、驱动、内核许可和安装升级验证。

## 已知交付边界

本地验证未开启 TUN，没有改动工作机路由、DNS、防火墙。未取得真实游戏线路凭据，不提供“韩服已可用”“已降低延迟”等无证据结论。

导入的第三方静态凭据由第三方管理；平台停止会话记录不能代替远端撤销。托管进程按租约关闭。

首版游戏由用户自行启动，进程命中需实测。断线出口保护与无感切换不在首版已验证能力内。

流量统计：落地节点的 ssserver 以 --manager-addr 每 10 秒把累计字节数报给 Agent，Agent 按会话累计（进程重启、Agent 重启后接着算）并单独上报，控制服务只接受会话落地节点的上报、只记增长，按会话和按小时（玩家、线路、游戏、服务器）保存。后台新增“流量统计”页（今天按小时、近 7 / 30 / 90 天按天的柱状图，悬停和键盘聚焦显示数值，附明细表；总流量、会话数、玩家数、平均每次会话；用量前十的玩家、线路、游戏、落地服务器），节点 Agent 低于 0.2.0 时页面提示更新；“加速会话”列表增加流量、时长和开始时间。验证：用真实的 shadowsocks-rust v1.25.0 ssserver 加 --manager-addr 经 sslocal 回显 1 MB，收到 stat: {"端口":2098451}（上传、下载与协议开销合计）；Agent 测试覆盖进程崩溃重启和 Agent 重启后累计不丢、停止后的最终值保留到上报成功；控制服务测试覆盖重复上报不重复计算、中转节点上报被忽略、验证会话不进统计、按天和按小时汇总；后台用本地种子数据（7 个玩家、30 天）在桌面和手机宽度下截图核对。图表单色 #c4881c 经 dataviz 校验对白底对比度 ≥ 3:1。

节点一键接入：后台“节点服务器”每行的“接入命令”生成一条带一次性凭据的命令，在节点服务器上用 root 运行即可完成安装、注册和开机自启；脚本和节点程序（Agent 以及固定版本、校验过的 ssserver、sslocal、Realm，x86_64 和 arm64）都由控制服务的 /dist/node/ 提供，节点只需能访问控制服务。再次运行同一命令（不带凭据）可更新节点程序。Go 测试覆盖脚本与程序的提供、SHA256SUMS 正确、白名单之外的文件和架构返回 404、接入命令带上 PUBLIC_URL；本机验证了从控制服务下载脚本和四个程序并通过校验，以及后台弹窗生成的命令。脚本在 Linux 上的完整运行（建账号、写配置、systemd 启动、注册、心跳、再次运行升级）由 CI 的 node-install 任务在 Ubuntu 上执行，本机没有 Linux 环境未运行。

安装程序：改为与客户端一致的深色向导（Inno Setup 6.7 的深色样式和背景图，图片由 installer/make-brand-assets.ps1 绘制）。首屏为品牌、简介、安装位置或“已安装 vX，将升级到 vY”、琥珀色“立即安装 / 立即升级 / 重新安装”按钮、“创建桌面快捷方式”（升级时沿用原来是否有快捷方式）；安装页为大标题和琥珀色进度条；完成页为“开始使用”和“立即启动”。安装过程和装好后的客户端都不向玩家显示服务器地址（客户端头像菜单里原来的“服务器 …”一行已去掉；连不上服务器时的报错不再带出 .NET 原文里的主机名，统一显示“无法连接服务器，请检查网络后重试”，隧道检测失败同样不带检测服务地址；“复制连接诊断”的内容也不再包含服务器地址，Windows 核心检查覆盖连不上时的提示）；地址填写页只在安装包没有内置地址时出现，运营方也可用 /CONTROLURL= 指定。可能导致报错的地方：升级时不再弹出“以下应用程序正在使用文件”的提示，也不会因客户端在托盘运行而文件被占用——准备阶段由新版脚本停止服务并关闭安装目录下的客户端和内核（只关这个目录里的进程）；加速服务配置失败不再弹出指向日志的报错框，而是在完成页按失败环节（内核被拦截或改动、旧服务停不下来、数据目录权限、服务注册失败、服务启动失败、PowerShell 不可用）写明原因、处理办法和安装记录位置。本地用预览版截图核对了全新安装、升级、同版本重装、服务启动失败和内核被拦截；关闭进程的逻辑用从构建目录启动的客户端验证过，只关闭了该目录下的进程。正式安装包需要管理员权限，没有在本机实际安装。

客户端更新：客户端连上本地服务后向控制服务查询最新稳定版（之后每 4 小时一次，头像菜单可手动检查），有新版本时游戏库顶部显示提示；可选更新可点“稍后”，必须更新（或跳过了某个必须更新的版本）不能关闭。点“立即更新”后下载到 `%LOCALAPPDATA%\FlowLightAccelerator\updates`，显示进度、可取消，下载后核对后台登记的 SHA256，不一致即删除；通过后先停止加速，再启动安装程序（安装程序自己请求管理员权限，这样它最后重新打开的客户端不带管理员权限）并留在原地等待：授权后安装程序关闭旧客户端、静默安装，完成后带 `/LAUNCH=1` 重新打开客户端，沿用原控制服务地址；拒绝授权时安装程序的启动进程先于客户端结束，客户端据此提示并恢复可用，“取消”会结束启动进程连同授权提示。查询接口不需要登录。本地验证（演练模式，下载校验后不启动安装程序）：用真实的 v0.1.5 安装包（95 MB）登记为 9.9.9，客户端提示、下载、校验通过；SHA256 填错时提示校验不一致并删除文件；必须更新时没有“稍后”；只发布更低版本时不提示；Go 测试覆盖免登录查询和跨过必须更新版本时仍要求更新。真正启动安装程序替换本机客户端的一步没有在本机执行，需要在发布 v0.1.6 后用下一个版本实测。
